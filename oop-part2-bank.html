Баланс меняют в обход правил

Поле баланса можно переписать напрямую: account.balance = 1_000_000. Банк не в курсе, проверки пропущены — на счёте миллион, которого не было.

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

account = BankAccount('Анна', 500)
account.balance = 1_000_000  # плохо: в обход правил!
print(account.balance)       # миллион, а операции не было
нарушение!
Прямая запись в поле обходит все проверки. Так теряются деньги.

Данные и правила — внутри счёта

Баланс и правила его изменения держим внутри счёта. Пополняем через deposit(), снимаем через withdraw() — они сами проверяют сумму. А узнаём баланс через get_balance().

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance
    def get_balance(self):
        return self.balance
    def deposit(self, amount):
        if amount > 0:
            self.balance += amount
        else:
            print('Сумма должна быть больше нуля!')
    def withdraw(self, amount):
        if 0 < amount <= self.balance:
            self.balance -= amount
        else:
            print('Недостаточно средств!')
Синее — данные. Зелёное — правила работы с ними.

Правила в одном месте

Пытаемся снять больше, чем есть, — получаем подсказку. Пополняем, потом снимаем — всё проходит.

# продолжение: класс BankAccount — на прошлом слайде
account = BankAccount('Анна', 500)
account.withdraw(1000)  # Недостаточно средств!
account.deposit(700)
account.withdraw(1000)
print(account.get_balance())  # 200 — но уже по правилам
Чек: правило написано 1 раз → действует для каждого счёта.
проверено!
Не надо помнить правила каждому: счёт следит за собой сам.
приём 1 · имена

Насколько закрыто?

В Python нет настоящего замка — есть договорённости. Смотри на имя и понимай, как с полем работать.

class BankAccount:
    def __init__(self, owner, balance):
        self.balance = balance      # обычное: открыто всем
        self._balance = balance     # внутреннее по договорённости
        self.__balance = balance    # Python переименует поле

account = BankAccount('Анна', 500)
print(account.balance)      # работает
print(account._balance)     # тоже работает — это лишь знак!
print(account._BankAccount__balance)  # найти можно и такое
Кстати: __init__ — особое имя с подчёркиваниями с обеих сторон. Это не приватный атрибут, а знак Python: «такие имена — служебные».
Ни один вариант — не надёжная защита. Методы помогают соблюдать правила, а подчёркивания показывают, что считать внутренним. Для проверки при записи — @property.

Короткий код не пройдёт

Снаружи — обычное поле account.secret_code. Внутри — проверка длины: минимум 5 символов.

class BankAccount:
    def __init__(self, secret_code):
        self.secret_code = secret_code

    @property
    def secret_code(self):
        return self._secret_code

    @secret_code.setter
    def secret_code(self, value):
        if len(value) < 5:
            print('Код должен быть не короче 5 символов!')
        else:
            self._secret_code = value
@property — метод, к которому обращаются как к полю. Без @secret_code.setter свойство будет только для чтения.
Короткий код не сохраняется — в поле остаётся прежнее значение.

Описываем требование

Что должен уметь любой способ оплаты? Проводить платёж: pay(amount). Записываем это требование классом PaymentMethod.

from abc import ABC, abstractmethod

class PaymentMethod(ABC):
    @abstractmethod
    def pay(self, amount):
        pass
@abstractmethod — просто пометка: «наследникам нужна своя реализация». Про декораторы подробно поговорим позже.
Пунктир — неспроста: создать такой класс напрямую нельзя, он только задаёт требование.
приём 2 · абстракция · варианты

Каждый отвечает по-своему

Два способа оплаты выполняют требование — каждый со своим ответом. Один цикл спрашивает у всех одно и то же.

# продолжение: PaymentMethod — на прошлом слайде
class CardPayment(PaymentMethod):
    def pay(self, amount):
        return f'Оплачено картой: {amount} ₽'

class CashPayment(PaymentMethod):
    def pay(self, amount):
        return f'Оплачено наличными: {amount} ₽'

for method in [CardPayment(), CashPayment()]:
    print(method.pay(500))
# Оплачено картой: 500 ₽
# Оплачено наличными: 500 ₽
Чек: ABC — инструмент, а не обязательное условие. Абстракция работает везде, где есть одинаковый вызов.
Не проверяем «а ты какой?» — просто спрашиваем у каждого.

Как храним и что требуем

Приёмы похожи, но отвечают на разные вопросы. На нашем счёте разница видна сразу.

  • Инкапсуляция — «данные и правила внутри»: баланс меняем через deposit() и withdraw(), а secret_code — через @property
  • Абстракция — «одно требование — разные ответы»: PaymentMethod требует pay(amount), варианты отвечают по-своему
Инкапсуляция — как храним. Абстракция — что требуем.
