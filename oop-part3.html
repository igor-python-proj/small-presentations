общее и своё

У класса — общее, у объекта — своё

Тот же Order. Три вопроса: что хранится у каждого заказа, что общее на всех и куда положить помощника.

Переменная класса
Одна на всех: налог, валюта, счётчик.
Метод класса
Работает с самим классом: удобный конструктор.
Статический метод
Просто помощник, живущий в классе.

На каждом слайде — тот же заказ, но показан только нужный кусок.

своё · переменные объекта

Своё — у каждого

Знакомое: self.pizza у каждого заказа своя. Поменял у одного — второй не заметил.

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

order1 = Order('Маргарита', 'Ленина 5')
order2 = Order('Пепперони', 'Мира 12')
print(order1.pizza)  # Маргарита
print(order2.pizza)  # Пепперони
order1.pizza = 'Четыре сыра'
print(order1.pizza)  # Четыре сыра
print(order2.pizza)  # Пепперони — не изменилась
Напоминание: self — это «эта самая карточка».
общее · переменная класса

Общее — одно на всех

Название пиццерии одинаковое для всех заказов — зачем копировать его в каждую карточку? Кладём в класс: поменяли один раз — увидели все.

class Order:
    restaurant_name = 'ПиццаДом'  # общее для всех заказов

    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

order1 = Order('Маргарита', 'Ленина 5')
order2 = Order('Пепперони', 'Мира 12')
print(order1.restaurant_name)  # ПиццаДом
print(order2.restaurant_name)  # ПиццаДом
Общее живёт в классе. Заказы только подглядывают — своего атрибута у них нет.
общее · нюанс

Своё перекрывает общее

Python ищет значение сначала у заказа, потом у класса. Записал имя в заказ — появился собственный атрибут, общее не меняется.

class Order:
    restaurant_name = 'ПиццаДом'  # общее для всех

    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

order1 = Order('Маргарита', 'Ленина 5')
order2 = Order('Пепперони', 'Мира 12')
order1.restaurant_name = 'Другая'  # собственный атрибут у order1!
Order.restaurant_name = 'ПиццаУгол'  # поменяли общее
print(order1.restaurant_name)  # Другая
print(order2.restaurant_name)  # ПиццаУгол
Собственный атрибут закрывает общий. У order2 своего нет — он смотрит в класс.
метод класса

Конструктор с именем

cls — это сам класс. Метод класса умеет создавать заказы удобным способом: Order.margherita(address) вместо полного вызова.

# самостоятельный пример: только нужное
class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

    @classmethod
    def margherita(cls, address):
        return cls('Маргарита', address)

order = Order.margherita('Ленина 5')
print(order.pizza)  # Маргарита
@classmethod — просто пометка (про декораторы — позже). Главное: первый аргумент cls, а не self.
Именованный конструктор: короткое имя вместо длинного вызова с деталями.
помощник · static

Просто функция в классе

Проверке промокода не нужны ни заказ, ни класс — только код. Кладём помощника в Order, чтобы лежал по теме.

# самостоятельный пример: только нужное
class Order:
    @staticmethod
    def is_promo(code):
        return code == 'PIZZA10'

print(Order.is_promo('PIZZA10'))  # True
print(Order.is_promo('ХЛЕБ'))  # False
Честно: часто хватит обычной функции вне класса. staticmethod — когда помощник логически про заказы и хочется держать его рядом.
Ни заказ, ни класс помощнику не нужны. Он просто лежит по теме.
разница · три слова

self, cls или ничего?

Смотри, что Python передаёт автоматически, — и сразу понятно, с чем метод работает.

  • self — Python передаёт объект: данные заказа (pizza, mark_ready())
  • cls — Python передаёт класс: общее (restaurant_name, margherita())
  • static — Python не передаёт ничего: аргументы даём сами (is_promo(code))
Три слова — три вида методов. Запомнишь их — не перепутаешь.
