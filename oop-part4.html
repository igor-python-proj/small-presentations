зачем · магия

Почему «магия»?

Магические (специальные) методы — методы с особыми именами. Python знает их и вызывает сам при привычных операциях. «Магия» — потому что вызова не видно в коде.

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

    def __str__(self):
        return f'Заказ: {self.pizza}'

order = Order('Маргарита', 'Ленина 5')
print(f'Заказ: {order.pizza}')  # форматируем вручную
print(order)  # Python вызывает __str__
Польза: результат одинаковый, но формат описан один раз в классе. Кстати, знакомый __init__ — тоже специальный метод: Python вызывает его при создании объекта. А вот имя вида __status — не такое: у него нет двух подчёркиваний в конце.
✦ ✦ ✦
Без магии можно — но с ней формат живёт в одном месте.
заклинание 1 · __str__

print() вызывает __str__

Без него печать показывает техническое описание объекта. С ним — красивый чек, понятный человеку.

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address
        self.status = 'готовится'

    def __str__(self):
        return f'Заказ: {self.pizza}, {self.address} ({self.status})'

order = Order('Маргарита', 'Ленина 5')
print(order)  # Заказ: Маргарита, Ленина 5 (готовится)
✦ ✦ ✦
Обычный вызов print — а внутри сработал твой __str__. Вывод расширили: дальше будут адрес и статус.
заклинание 2 · __repr__

repr() — для разработчика

__str__ — красиво человеку. __repr__ — точно разработчику: видно, что внутри объекта. Его часто пишут так, чтобы объект можно было пересоздать. Кстати: нет __str__ — print использует __repr__.

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

    def __repr__(self):
        return f'Order({self.pizza!r}, {self.address!r})'

order = Order('Маргарита', 'Ленина 5')
print(repr(order))  # Order('Маргарита', 'Ленина 5')
✦ ✦ ✦
Витрина — для людей, кухня — для своих. Оба нужны.
заклинание 3 · __eq__

== сравнивает по-твоему

Без __eq__ два разных объекта нашего Order по умолчанию не равны — даже с одинаковой начинкой. С __eq__ сравниваем по содержимому: пицца и адрес совпали — заказы равны. Неравенство != прилагается само. Совпадение пиццы и адреса — правило нашего примера, не закон жизни.

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address

    def __eq__(self, other):
        if not isinstance(other, Order):
            return NotImplemented
        return (self.pizza, self.address) == (other.pizza, other.address)

order1 = Order('Маргарита', 'Ленина 5')
order2 = Order('Маргарита', 'Ленина 5')
order3 = Order('Пепперони', 'Ленина 5')
print(order1 == order2)  # True
print(order1 == order3)  # False
Разбор: isinstance проверяет, заказ ли перед нами. NotImplemented значит «не знаю, пусть решает Python» — тогда сравнение с числом спокойно даёт False.
✦ ✦ ✦
Одинаковые карточки — разные объекты. Сравниваем начинку, а не обложку.
заклинания 4–5 · __len__ __contains__

Меню знает свой размер

Новый герой — Menu, список блюд. len(menu) считает позиции, а in проверяет наличие — оба через твои методы.

class Menu:
    def __init__(self, dishes):
        self.dishes = dishes

    def __len__(self):
        return len(self.dishes)

    def __contains__(self, dish):
        return dish in self.dishes

menu = Menu(['Маргарита', 'Пепперони'])
print(len(menu))  # 2
print('Маргарита' in menu)  # True
✦ ✦ ✦
Два заклинания — и меню поддерживает len() и in, как список.
заклинание 6 · __add__

+ склеивает меню

Плюс складывает два меню в одно: блюда объединяются. Тот же класс Menu плюс новый метод — остальное без изменений.

# тот же класс Menu плюс новый метод __add__
class Menu:
    def __init__(self, dishes):
        self.dishes = dishes

    def __len__(self):
        return len(self.dishes)

    def __contains__(self, dish):
        return dish in self.dishes

    def __add__(self, other):
        return Menu(self.dishes + other.dishes)

morning = Menu(['Маргарита'])
evening = Menu(['Пепперони'])
day = morning + evening
print(day.dishes)  # ['Маргарита', 'Пепперони']
print(len(day))  # 2 — старые методы на месте
✦ ✦ ✦
Обычный плюс — а внутри твой метод решает, что значит «сложить».

Шесть заклинаний одной таблицей

Слева — привычная запись. Справа — метод, который Python вызовет сам.

  • print(order) → __str__ — красивый чек
  • repr(order) → __repr__ — точное описание
  • order1 == order2 → __eq__ — сравнение по содержимому
  • len(menu) → __len__ — размер коллекции
  • 'Маргарита' in menu → __contains__ — проверка наличия
  • morning + evening → __add__ — сложение по-твоему
✦ ✦ ✦
Никакой магии: назвал метод правильно — Python нашёл его сам.
