Где таблица подводит

Порядок есть. Правил — нет

Таблицу заполняет игра. А игра — это руки программиста, который торопится и ошибается. Таблица молча принимает всё.

  • «Очень редкая прям» в колонке rarity — таблица приняла. Сравнить редкости потом не выйдет.
  • Предмет без имени — строка есть, а предмета нет. Запретить пустое некому.
  • Меч в двух строках — это один предмет или два? Дубликатов никто не ловит.
Зерно: правила должен соблюдать кто-то, кто не устаёт. Нужен файл, который следит за порядком сам.

Словарь

Строка — запись. Колонка — свойство

Кликните по строке и по названию колонки — таблица подскажет, что есть что.

  • Строка — одна запись целиком: один предмет со всеми свойствами.
  • Колонка — одно свойство, одинаковое у всех строк.
  • Несколько таблиц — в одной базе каждая про своё: player — про героя, items — про рюкзак.
  • id — уникальный номер записи. База назначает его сама и больше не меняет.
Зачем id: строка №3 плавает при вставках и удалениях, а id = 3 — нет. Именно его используют UPDATE и DELETE.

Готовое решение

SQLite: вся база — один файл

Всё, что мы сформулировали, уже сделано за нас. SQLite — это база данных, которая живёт в одном файле рядом с программой.

  • Вся база — один файл saves.db: скопировать, перенести, удалить.
  • Сервер не нужен: база рядом с программой, как обычный файл.
  • Модуль sqlite3 в Python уже есть — ничего ставить не нужно.
  • Такая база стоит в каждом телефоне: чаты, заметки, настройки — и в консолях, и в браузерах.
проект
game/
  ├─ game.py        ← игра
  └─ saves.db       ← вся база сохранений: один файл
Внутри — таблицы: player (уровень, монеты) и items (рюкзак). Правила — типы, уникальные id, обязательные поля — файл проверяет сам.
Порядок работы: открыл файл → попросил на SQL → получил ответ → закрыл.

Паспорт таблиц

CREATE TABLE — правила один раз

Колонки и правила описываются один раз — дальше таблицы проверяют сами. Кликните по строке паспорта.

  • Типы: в колонке числа — только числа, текст — только текст.
  • PRIMARY KEY — уникальный номер строки: повторить нельзя.
  • NOT NULL — пустым оставлять нельзя.
  • IF NOT EXISTS — повторный запуск скрипта не упадёт: таблицы уже есть.
паспорт
schema.sql — паспорт таблиц сохранения
CREATE TABLE IF NOT EXISTS items (
  id     INTEGER PRIMARY KEY,
  name   TEXT NOT NULL,
  rarity TEXT,
  count  INTEGER
);
CREATE TABLE IF NOT EXISTS player (
  level  INTEGER,  coins  INTEGER
);
— клик по строке паспорта —
Колонки — это договор: в каждой строке на этом месте лежит одно и то же свойство, и оно одного типа.

Python · дроп

connect → execute → commit

С базой говорят тремя шагами: открыть файл, выполнить SQL, сохранить изменения в файле.

import sqlite3

# открыть базу: файла нет — создастся
conn = sqlite3.connect('saves.db')

conn.execute("""
INSERT INTO items (name, rarity, count)
VALUES (?, ?, ?)
""", ("сундук", "редкий", 1))
conn.commit()   # сохранить в файл
conn.close()
  • ? — места подстановки: данные идут отдельно от текста запроса. Почему это важно — на слайде про инъекции.
  • commit() — «нажать сохранить»: без него изменения не попадут в файл.

Python · прокачка

UPDATE — прогресс растёт

Игрок что-то делает каждые десять секунд — и каждое действие меняет сохранение. Каждое изменение — это один UPDATE.

conn.execute("UPDATE player SET level = level + 1")

# ("меч",) — кортеж: запятая внутри обязательна
conn.execute("""
UPDATE items SET count = count + 1
WHERE name = ?
""", ("меч",))
conn.commit()
  • SET level = level + 1 — «стало на один больше»: база сама посчитает.
  • WHERE — «кому именно»: апгрейдится один предмет, а не весь рюкзак.
Прогресс — это много UPDATE поверх состояния. Сохранение всегда говорит «сейчас».

Кому именно

Без WHERE — честно выполнит для всех

UPDATE и DELETE сами не догадываются, кого вы имели в виду. Нет WHERE — все строки.

-- ⚠ без WHERE: выполнит для всех строк
UPDATE items SET count = 0;
DELETE FROM items;

-- правильно: по номеру записи
DELETE FROM items WHERE id = 3;
  • WHERE — «кому именно»: апгрейд одного предмета, продажа одного предмета.
  • Продать «щит» — это DELETE … WHERE id = 3: номер записи, а не строка в таблице.
Одно нажатие без WHERE — и инвентарь пуст. База не предупредит: команда честная.

Python · спросить

SELECT — скажи, что нужно

В Python вы описываете как искать: цикл и проверки. В SQL вы просто говорите, что вам нужно:

# питон: КАК искать
rare = []
for it in items:
    if it['rarity'] == 'легендарный':
        rare.append(it)
-- SQL: ЧТО нужно
SELECT * FROM items
WHERE rarity = 'легендарный';
  • fetchall() — все строки; fetchone() — первая (или None); fetchmany(3) — не больше трёх.
  • WHERE работает и с текстом, и с числами: rarity = ?, count > 1.

Две ловушки

commit и SQL-инъекция

Забыли commit(): изменения живут в памяти соединения. Закрыли игру — прогресс откатился. INSERT / UPDATE / DELETE — и следом commit().
Склеили строку с запросом: данные стали частью команды. Тролль из чата вписал в ник '); DELETE FROM items;-- — рюкзак опустел.
conn.execute("""
INSERT INTO items (name, rarity, count)
VALUES (?, ?, ?)
""", ("скин", "легендарный", 1))

conn.commit()   # ← без этой строки скин исчезнет
Решение — ?: данные идут отдельным параметром. База знает: это значение, а не команда. Любой текст просто ляжет в колонку name.

Запомнить

Сохранение — это таблица в файле

1 · состояние, не история
Таблица хранит «сейчас»: уровень, монеты, рюкзак. Журнал — история событий: чтобы узнать «что у меня есть», её надо пересчитать.
2 · UPDATE и DELETE
Меняют и удаляют строки — почти всегда с WHERE id. Без WHERE — всем строкам сразу.
3 · commit()
«Нажать сохранить». Без него прогресс откатится при закрытии соединения.
4 · ?
Данные отдельно от запроса: тролли в чате бессильны.
Так устроены сохранения в играх — и не только: заметки, чаты, банковские приложения. Везде, где данные должны пережить перезапуск.
