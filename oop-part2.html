проблема · руки внутрь

Статус меняют мимо кассы

Поле статуса можно переписать напрямую: order.status = 'доставлен'. Кухня не в курсе, проверки пропущены — пицца ещё в печи, а заказ уже «доставлен».

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address
        self.status = 'готовится'

order = Order('Маргарита', 'Ленина 5')
order.status = 'доставлен'  # плохо: в обход правил!
print(order.status)  # доставлен, а пицца ещё в печи
нарушение!
Прямая запись в поле обходит все проверки. Так ломаются заказы.

Данные и правила — внутри заказа

Статус и правила его смены — внутри заказа. Меняем через mark_ready() и mark_delivered(): они проверяют порядок. Читаем через get_status().

class Order:
    def __init__(self, pizza, address):
        self.pizza = pizza
        self.address = address
        self.status = 'готовится'
    def get_status(self):
        return self.status
    def mark_ready(self):
        if self.status == 'готовится':
            self.status = 'готов'
        else:
            print('Пицца уже вышла из кухни!')
    def mark_delivered(self):
        if self.status == 'готов':
            self.status = 'доставлен'
        else:
            print('Сначала приготовьте пиццу!')
Красное — данные. Зелёное — правила работы с ними.
приём 1 · проверка

Правила в одном месте

Пытаемся доставить неготовый заказ — получаем подсказку. Готовим, потом доставляем — всё проходит.

# продолжение: класс Order — на прошлом слайде
order = Order('Маргарита', 'Ленина 5')
order.mark_delivered()  # Сначала приготовьте пиццу!
order.mark_ready()
order.mark_delivered()
print(order.get_status())  # доставлен — но уже по правилам
Чек: правило написано 1 раз → действует для каждого заказа.
проверено!
Не надо помнить правила каждому: заказ следит за собой сам.
приём 1 · имена

Насколько закрыто?

В Python нет настоящего замка — есть договорённости. Смотри на имя и понимай, как с полем работать.

class Order:
    def __init__(self, pizza, address):
        self.status = 'готовится'     # обычное: открыто всем
        self._status = 'готовится'    # внутреннее по договорённости
        self.__status = 'готовится'   # Python переименует поле

order = Order('Маргарита', 'Ленина 5')
print(order.status)    # работает
print(order._status)   # тоже работает — это лишь знак!
print(order._Order__status)  # найти можно и такое
Кстати: __init__ — особое имя с подчёркиваниями с обеих сторон. Это не приватный атрибут, а знак Python: «такие имена — служебные».
Ни один вариант — не надёжная защита. Методы помогают соблюдать правила, а подчёркивания показывают, что считать внутренним.

Описываем требование

Что должен уметь любой способ получения заказа? Отвечать на how_to_receive(). Записываем это требование классом ReceivingMethod.

from abc import ABC, abstractmethod

class ReceivingMethod(ABC):
    @abstractmethod
    def how_to_receive(self):
        pass
@abstractmethod — просто пометка: «наследникам нужна своя реализация». Про декораторы подробно поговорим позже.
Пунктир — неспроста: создать такой класс напрямую нельзя, он только задаёт требование.
приём 2 · абстракция · варианты

Каждый отвечает по-своему

Два способа получения выполняют требование — каждый со своим ответом. Один цикл спрашивает у всех одно и то же.

# продолжение: ReceivingMethod — на прошлом слайде
class CourierDelivery(ReceivingMethod):
    def how_to_receive(self):
        return 'Курьер привезёт заказ'

class Pickup(ReceivingMethod):
    def how_to_receive(self):
        return 'Заберите заказ в пиццерии'

for way in [CourierDelivery(), Pickup()]:
    print(way.how_to_receive())
# Курьер привезёт заказ
# Заберите заказ в пиццерии
Чек: ABC — инструмент, а не обязательное условие. Абстракция работает везде, где есть одинаковый вызов.
Не проверяем «а ты какой?» — просто спрашиваем у каждого.
два приёма · разница

Как храним и что требуем

Приёмы похожи, но отвечают на разные вопросы. На наших заказах разница видна сразу.

  • Инкапсуляция — «данные и правила внутри»: статус заказа меняем через mark_ready() и mark_delivered()
  • Абстракция — «одно требование — разные ответы»: ReceivingMethod требует how_to_receive(), варианты отвечают по-своему
Инкапсуляция — как храним. Абстракция — что требуем.
