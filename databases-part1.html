Где таблица подводит

Порядок есть. Правил — нет

Таблицу заполняют руки. Руки торопятся и ошибаются — и таблица молча принимает всё подряд.

  • «Ага» в ячейке — не ✓ и не ✗, но таблица приняла. Программа потом не поймёт.
  • Дубликат: «собрать катку» в двух строках. Какое из двух актуально?
  • «Удали дело №3» — а добавили новую строку, и №3 уже другое дело.
Зерно: правила должен соблюдать кто-то, кто не устаёт. Нужен файл, который следит за порядком сам.

Словарь

Строка — запись. Колонка — свойство

Кликните по строке и по названию колонки — таблица подскажет, что есть что.

  • Строка — одна запись целиком: одно дело со всеми свойствами.
  • Колонка — одно свойство, одинаковое у всех строк.
  • id — уникальный номер записи. Его назначает база и больше не меняет: «дело №2» — это всегда одно и то же дело.
Зачем id: строка №3 в таблице плавает при вставках и удалениях, а id = 3 — нет. Именно его используют UPDATE и DELETE.

Готовое решение

SQLite: вся база — один файл

Всё, что мы сформулировали, уже сделано за нас. SQLite — это база данных, которая живёт в одном файле рядом с программой.

  • Вся база — один файл database.db: скопировать, перенести на флешку, удалить.
  • Сервер не нужен: база рядом с программой, как обычный файл.
  • Модуль sqlite3 в Python уже есть — ничего ставить не нужно.
  • Такая база стоит в каждом телефоне: чаты, заметки, настройки — всё в файлах SQLite.
проект
проект/
  ├─ main.py         ← программа
  ├─ database.db     ← вся база: один файл
  └─ lessons/
Внутри — таблицы. Например, todos: те же строки с делами из попытки №3, только правила — типы, уникальные id, обязательные поля — файл проверяет сам.
Порядок работы: открыл файл → попросил на SQL → получил ответ → закрыл.

Паспорт таблицы

CREATE TABLE — правила один раз

Колонки и правила описываются один раз — дальше таблица проверяет сама. Кликните по строке паспорта.

  • Типы: в колонке числа — только числа, текст — только текст.
  • PRIMARY KEY — уникальный номер строки: повторить нельзя.
  • NOT NULL — пустым оставлять нельзя.
  • IF NOT EXISTS — повторный запуск скрипта не упадёт: таблица уже есть.
паспорт
schema.sql — паспорт таблицы todos
CREATE TABLE IF NOT EXISTS todos (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  description  TEXT,
  done        INTEGER
);

Python · положить

connect → execute → commit

С базой говорят тремя шагами: открыть файл, выполнить SQL, сохранить изменения в файле.

import sqlite3

# открыть базу: файла нет — создастся
conn = sqlite3.connect('database.db')

conn.execute(
    "INSERT INTO todos (name, description, done)"
    " VALUES (?, ?, ?)",
    ("разобрать рюкзак", "после пар", 0),
)
conn.commit()   # сохранить в файл
conn.close()
  • ? — места подстановки: данные идут отдельно от текста запроса. Почему это важно — на слайде про инъекции.
  • commit() — «нажать сохранить»: без него изменения не попадут в файл.

Python · спросить

SELECT — скажи, что нужно

В Python вы описываете как искать: цикл и проверки. В SQL вы просто говорите, что вам нужно:

# питон: КАК
left = []
for t in todos:
    if t['done'] == 0:
        left.append(t)
-- SQL: ЧТО
SELECT * FROM todos
WHERE done = 0;
  • fetchall() — все строки; fetchone() — первая (или None); fetchmany(3) — не больше трёх.
  • WHERE — фильтр: дай только те, у которых done = 0.

Четыре глагола

Кнопки приложения — это SQL

Любое приложение с данными делает ровно четыре вещи. Каждая кнопка — одна команда базе:

INSERT INTO todos (name, description, done)
    VALUES (?, ?, ?)             -- положить
SELECT * FROM todos              -- посмотреть
UPDATE todos SET done = 1
    WHERE id = 3                 -- изменить
DELETE FROM todos WHERE id = 2  -- удалить
  • WHERE id = … — «кому именно»: изменить или удалить одну запись по номеру.
  • Без WHERE UPDATE изменит все строки, DELETE — удалит всё. База честно выполнит.

Ловушка №1

Забыли commit() — изменений нет

Пока не вызван commit(), изменения живут только в памяти соединения. Файл database.db про них не знает.

conn.execute("INSERT INTO todos (name, done)"
             " VALUES (?, ?)", ("выспаться", 0))

conn.commit()   # ← сохранить: без этой строки INSERT пропадёт
conn.close()
  • Справа: INSERT — строка появилась. Но она в памяти соединения.
  • Выключите commit и закройте соединение.
  • База открывается заново — строки нет. Она честная: её никто не сохранил.
Правило: INSERT / UPDATE / DELETE — и следом commit(). После SELECT сохранять нечего.

Ловушка №2

SQL-инъекция: строки нельзя склеивать

Если вставить данные прямо в текст запроса, данные становятся частью команды. Представьте, что в поле «новое дело» вписали:

выспаться'); DELETE FROM todos;--

Склейка строк даст базе две команды вместо одной:

INSERT INTO todos (name, done) VALUES ('выспаться');
DELETE FROM todos; --', 0)  ← после -- это комментарий

INSERT добавил дело — а следом DELETE стёр все дела. Троллю даже не нужен был доступ к базе.

Решение — ?: данные идут отдельным параметром. База знает: это значение, а не команда. Весь этот текст просто ляжет в колонку name.
